## 2. 발견된 버그

### BUG-01: `todos` 테이블 `start_date` 컬럼 누락 (Critical — 수정 완료)

- **증상:** `POST /api/todos` 호출 시 500 Internal Server Error
- **원인:** `backend/src/repositories/todo.repository.js`의 INSERT 쿼리에 `start_date` 컬럼을 포함하나, DB 테이블에 해당 컬럼이 없었음
- **조치:** `ALTER TABLE todos ADD COLUMN start_date DATE;` 실행으로 수정 완료
- **영향 범위:** S-04 (할일 등록), S-05 (할일 수정) 전반

### BUG-02: S-03 프로필 이름 변경 후 UI 즉시 갱신 미반영 (Minor — 수정 완료)

- **증상:** 이름 변경 API 호출 성공 (DB 반영 확인) 후에도 프로필 화면의 "현재 계정" 영역에 기존 이름이 표시됨
- **원인:** `PATCH /api/users/me` 성공 후 TanStack Query의 `['me']` 캐시를 무효화하지 않아 `meData`가 구 데이터를 계속 반환
- **조치:** `frontend/src/pages/ProfilePage.tsx` — `nameUpdateMutation`의 `onSuccess`에서 `queryClient.invalidateQueries({ queryKey: ['me'] })` 추가
- **검증:** 이름 변경 후 "현재 계정" 카드 즉시 갱신 확인

## 3. 시나리오별 상세 결과

### S-01: 회원가입
- **기본 흐름:** 이름·이메일·비밀번호 입력 → 가입하기 클릭 → `/login` 이동 ✅
- **사후 조건:** users 테이블 레코드 생성 확인 (user_id=31, provider='local')

### S-02: 로그인
- **기본 흐름:** 이메일·비밀번호 입력 → 로그인 클릭 → `/` 이동 ✅
- **사후 조건:** Zustand 메모리에 토큰 저장 (페이지 새로고침 시 소멸 — 시나리오 명세 일치)

### S-03: 개인정보 수정 (이름)
- **기본 흐름:** 이름 입력 → 이름 변경 버튼 → DB 업데이트 성공 ✅
- **UI 버그:** 성공 후 화면에 반영되지 않음 ⚠️ (BUG-02)

### S-04: 할일 등록
- **초기 실패:** `start_date` 컬럼 누락으로 500 에러 (BUG-01 수정 후 재테스트)
- **수정 후 기본 흐름:** 제목 + 카테고리(업무) 입력 → 등록 → 목록에 표시 ✅
- **사후 조건:** 요약 카드 "오늘 할일: 1", "미완료: 2" 반영 확인

### S-05: 할일 수정
- **기본 흐름:** Edit 버튼 → 수정 다이얼로그 → 종료일 2026-05-15 → 2026-05-22 변경 → 저장 ✅
- **사후 조건:** DB `due_date` 갱신 확인 (2026-05-22), 카드 UI 반영 확인

### S-06: 할일 삭제
- **기본 흐름:** Del 버튼 → "정말 삭제하시겠습니까?" 확인 다이얼로그 → 삭제 → 목록에서 제거 ✅
- **사후 조건:** 미완료 카운트 2→1 감소 확인

### S-07: 완료 상태 토글
- **미완료→완료:** 체크박스 클릭 → `[checked]` 상태 + "완료" 표시 ✅
- **완료→미완료:** 체크박스 재클릭 → 체크 해제 + "미완료" 표시 ✅

### S-08: 할일 목록 조회 및 필터
- **완료 여부 필터:** "완료" 선택 시 완료 할일 0건 → 빈 목록 표시 ✅
- **카테고리 필터:** 카테고리 드롭다운 동작 확인 (테스트카테고리 포함 표시)

### S-09: 카테고리 추가
- **기본 흐름:** 카테고리 이름 입력 → 추가 → 목록 갱신 ✅
- **사후 조건:** 전체 6개, 사용자 1개 카운트 반영 확인

### S-10: 카테고리 삭제
- **BR-05 검증:** 기본 카테고리에 삭제 버튼 미표시 — UI 레벨에서 보호 ✅
- **기본 흐름:** 테스트카테고리 삭제 버튼 → 확인 다이얼로그 → 삭제 → 목록 갱신 ✅
- **사후 조건:** 전체 5개, 사용자 0개 카운트 반영 확인

### S-11: 로그아웃
- **기본 흐름:** 로그아웃 버튼 → `/login` 이동 ✅
- **사후 조건:** Zustand 토큰 초기화 확인 (이후 /categories 직접 접근 시 /login 리디렉션 확인)

### S-12: 토큰 갱신
- **방식:** Zustand 메모리 기반 — 페이지 새로고침 시 토큰 소멸하여 /login으로 리디렉션됨
- **확인:** 새로고침 후 인증 필요 페이지(/categories) 접근 시 /login 이동 확인 ✅

### S-13: 회원 탈퇴
- **기본 흐름:** 회원 탈퇴 버튼 → 경고 다이얼로그 → 비밀번호 입력 → 탈퇴하기 → `/login` 이동 ✅
- **사후 조건:** DB에서 users(email=e2e_test_20260515@example.com), todos(user_id=31) 전체 삭제 확인
