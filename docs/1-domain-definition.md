# TodoListApp 도메인 정의서

**버전:** 1.0
**작성일:** 2026-05-12
**작성자:** Business Analyst

---

## 1. 프로젝트 개요

### 문제 정의

- 개인 단위로 할일을 체계적으로 관리할 수 있는 전용 애플리케이션이 부재하다.
- 인증된 사용자 기반으로 데이터베이스에 할일을 안전하게 저장하고 관리하는 수단이 없다.
- 카테고리를 활용하여 할일을 분류·관리할 수 있는 기능이 제공되지 않고 있다.

### 목표

인증 기반의 개인 할일 관리 애플리케이션을 제공하여, 사용자가 자신의 할일을 카테고리별로 등록·조회·완료 처리할 수 있도록 한다.

---

## 2. 핵심 도메인 용어 정의 (Ubiquitous Language)

| 용어 | 정의 |
|------|------|
| **사용자 (User)** | 회원가입 후 인증을 통해 앱을 사용하는 주체 |
| **인증 (Authentication)** | 사용자가 본인임을 확인하는 로그인 절차 |
| **할일 (Todo)** | 사용자가 등록한 수행 예정 작업 단위 |
| **카테고리 (Category)** | 할일을 분류하기 위한 그룹 레이블 |
| **기본 카테고리 (Default Category)** | 시스템이 사전 제공하는 기본 분류 항목 |
| **사용자 정의 카테고리 (Custom Category)** | 사용자가 직접 추가한 분류 항목 |
| **종료 예정일 (Due Date)** | 할일을 완료하기로 계획한 날짜 |
| **완료 여부 (Completion Status)** | 할일의 수행 완료 상태 (완료 / 미완료) |
| **필터 (Filter)** | 할일 목록 조회 시 특정 조건으로 결과를 좁히는 기능 |

---

## 3. 도메인 모델

### 3-1. 주요 엔티티와 속성

**User (사용자)**
- `user_id` : 고유 식별자 (PK)
- `email` : 이메일 주소 (로그인 ID, 고유값)
- `password` : 암호화된 비밀번호
- `name` : 사용자 이름
- `created_at` : 가입 일시

**Category (카테고리)**
- `category_id` : 고유 식별자 (PK)
- `user_id` : 소유 사용자 (FK, null이면 기본 카테고리)
- `name` : 카테고리명
- `is_default` : 기본 카테고리 여부

**Todo (할일)**
- `todo_id` : 고유 식별자 (PK)
- `user_id` : 소유 사용자 (FK)
- `category_id` : 분류 카테고리 (FK)
- `title` : 할일 제목
- `description` : 설명
- `due_date` : 종료 예정일
- `is_completed` : 완료 여부
- `created_at` : 등록 일시
- `updated_at` : 수정 일시

### 3-2. 엔티티 관계

```
User (1) ──────< Todo (N)
User (1) ──────< Category (N)   ← 사용자 정의 카테고리
Category (1) ──< Todo (N)
```

- 한 명의 사용자는 여러 개의 할일을 소유한다.
- 한 명의 사용자는 여러 개의 사용자 정의 카테고리를 생성할 수 있다.
- 기본 카테고리는 시스템 소유이며 모든 사용자가 공유한다.
- 하나의 할일은 반드시 하나의 카테고리에 속한다.

## 4. 핵심 비즈니스 규칙

| # | 규칙 |
|---|------|
| BR-01 | 회원가입 시 이메일은 시스템 내 고유해야 한다. |
| BR-02 | 할일은 반드시 인증된 사용자만 등록·수정·삭제할 수 있다. |
| BR-03 | 사용자는 자신이 소유한 할일과 카테고리에만 접근할 수 있다. |
| BR-04 | 할일 등록 시 카테고리는 필수이며, 기본 카테고리 또는 사용자 정의 카테고리 중 하나여야 한다. |
| BR-05 | 기본 카테고리는 사용자가 수정하거나 삭제할 수 없다. |
| BR-06 | 할일의 종료 예정일은 과거 날짜도 허용하나, 신규 등록 시에는 오늘 이후 날짜를 권장한다. |
| BR-07 | 할일 완료 처리 후에도 목록에서 조회 가능하며, 완료 취소(되돌리기)가 가능하다. |
| BR-08 | 카테고리 삭제 시 해당 카테고리에 속한 할일이 존재하면 삭제할 수 없다. |

## 5. 주요 유스케이스

| UC | 유스케이스명 | 행위자 | 요약 |
|----|------------|--------|------|
| UC-01 | 회원가입 | 비인증 사용자 | 이메일·비밀번호·이름을 입력해 계정을 생성한다. |
| UC-02 | 로그인 | 비인증 사용자 | 이메일·비밀번호로 인증하여 서비스에 접근한다. |
| UC-03 | 개인정보 수정 | 인증된 사용자 | 자신의 이름·비밀번호 등 개인정보를 변경한다. |
| UC-04 | 할일 등록 | 인증된 사용자 | 제목·설명·종료 예정일·카테고리를 입력해 할일을 생성한다. |
| UC-05 | 할일 수정 | 인증된 사용자 | 기존 할일의 항목을 변경한다. |
| UC-06 | 할일 삭제 | 인증된 사용자 | 등록된 할일을 삭제한다. |
| UC-07 | 할일 완료 처리 | 인증된 사용자 | 할일의 완료 상태를 전환(완료 ↔ 미완료)한다. |
| UC-08 | 할일 목록 조회 | 인증된 사용자 | 카테고리·기간·완료 여부 조건으로 필터링하여 목록을 조회한다. |
| UC-09 | 카테고리 추가 | 인증된 사용자 | 기본 카테고리 외 사용자 정의 카테고리를 생성한다. |
| UC-10 | 카테고리 삭제 | 인증된 사용자 | 할일이 없는 사용자 정의 카테고리를 삭제한다. |
